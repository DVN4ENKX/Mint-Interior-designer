# 🏠 Room Planner — 3D-планировщик квартиры

Веб-приложение для ремонта и расстановки мебели: нарисуйте планировку в 2D (или обведите загруженное фото плана), откалибруйте масштаб по известному размеру — и сразу получите 3D-комнату, в которой можно расставлять мебель из каталога или свои собственные `.glb`-модели.

**Архитектурный принцип:** один store — две проекции. 2D-холст (Konva) и 3D-сцена (React Three Fiber) рендерят одни и те же данные в метрах, поэтому всё, что нарисовано в 2D, мгновенно и точно появляется в 3D.

## Возможности

- **2D-редактор**: стены кликами (цепочкой), доводка до осей, сетка 0.5 м, выбор/перетаскивание узлов/удаление стен, автоматические размеры в метрах.
- **Двери и окна**: ставятся кликом по стене, тащатся вдоль стены, края меняют ширину; в 3D стены сегментируются (косяки + фрамуга над дверью, подоконник + проём под окном).
- **Подложка из фото плана** с калибровкой масштаба: две точки + реальная длина → честный масштаб (`м/px`). Фото и пользовательские модели хранятся в **IndexedDB** и переживают перезагрузку страницы.
- **Цвет стен («обои»)**: каждой стене свой цвет, кнопка «Ко всем стенам» — применяется и в 2D, и в 3D.
- **3D-сцена**: стены объёмом (высота 2.7 м), тени, орбитальная камера, перетаскивание мебели мышью по полу, поворот на 10° двойным кликом.
- **Каталог мебели** с категориями (Мебель/Освещение/Текстиль/Декор), поиском, чипами-фильтрами и секцией «В комнате» с корзиной; загрузка собственных `.glb/.gltf` (габариты считаются из геометрии автоматически).
- **3D из фото (TripoSR)**: одно фото объекта + реальная высота в метрах → отдельный Python-сервис строит 3D-модель (scikit-image вместо torchmcubes, работает на CPU) в честном масштабе; результат попадает в каталог как обычная модель.
- **Коллизии мебели**: при перетаскивании (в 3D и на плане) предмет не может въехать в другую мебель — пересечение повёрнутых прямоугольников проверяется через SAT; плоские предметы (ковры) исключены.
- **Мебель на плане**: схематичный вид сверху (Konva), перетаскивание и поворот на 90° двойным кликом.
- **Undo/redo** (`Ctrl+Z` / `Ctrl+Shift+Z`) на всю историю действий, включая drag одним шагом.
- **Аккаунты и облако**: регистрация/вход (свой backend на Node + Postgres, JWT), сохранение проектов, **шаринг публичных ссылок** `#p=<uuid>` — чужой проект открывается в режиме просмотра, сохранение создаёт личную копию (форк).
- **Экспорт/импорт** проекта в JSON, скриншот сцены в PNG.
- **Автосохранение** локальной копии в localStorage.
- **Современный UI (Glassmorphism)**: тёмная тема с полупрозрачными «стеклянными» панелями, `backdrop-filter: blur`, плавающими световыми пятнами на фоне и акцентной палитрой mint/cherry.

## Быстрый старт (разработка)

Требуются: **Node 20+**, **Docker**.

```bash
# 1. зависимости фронтенда
npm install

# 2. база данных
docker compose up -d db

# 3. API-сервер
cd server
npm install
npm run dev          # → http://localhost:8787

# 4. Python-сервис TripoSR (только для функции «3D из фото»)
cd reconstructor
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app:app --host 0.0.0.0 --port 8788
# первый запуск скачает веса TripoSR (~700 МБ) и rembg/u2net (~170 МБ)

# 5. фронтенд (в новом терминале)
npm run dev          # → http://localhost:5173
```

Проверка типов: `npm run build`.

## API

| Метод | Путь | Auth | Описание |
|---|---|---|---|
| POST | `/api/auth/register` | — | регистрация; возвращает `{ id, email, token }` |
| POST | `/api/auth/login` | — | вход; возвращает `{ id, email, token }` |
| GET | `/api/me` | ✅ | текущий пользователь |
| POST | `/api/projects` | ✅ | создать проект (`data: jsonb`) |
| PUT | `/api/projects/:id` | ✅ владелец | обновить данные проекта |
| POST | `/api/projects/:id/share` | ✅ владелец | сделать публичным |
| GET | `/api/projects/:id` | опционально | прочитать: владелец **или** любой, если `is_public` |

Пароли хранятся как `scrypt`-хеш с солью; доступ к чужим приватным проектам закрыт на уровне SQL-запросов (`owner_id` / `is_public`).

## Сервис реконструкции (TripoSR)

Python-сервис в `reconstructor/` генерирует 3D-модель из одного фото. Кнопка «📷 3D из фото» в каталоге отправляет фото и реальную высоту объекта (м), сервис опрашивается, готовый `.glb` попадает в каталог как обычная модель — габариты читаются из геометрии, поэтому масштаб честный.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/reconstruct` | `multipart`-запрос (`image`, `height`, `name?`); возвращает `{ job_id }` |
| GET | `/api/reconstruct/:id` | `{ status: queued\|processing\|done\|error, size?, error? }` |
| GET | `/api/reconstruct/:id/file` | готовый `.glb` (только при `status: done`) |

Особенности:

- **CPU-режим**: без GPU генерация занимает ~0.5–5 минут на фото; скорость регулируется `MC_RESOLUTION` (по умолчанию 192).
- **Замена torchmcubes**: у него нет колёс под Windows/py3.13, поэтому `reconstructor/fakemods/torchmcubes.py` реализует тот же API через scikit-image (оригинальный код TripoSR не меняется).
- **Ориентация и масштаб**: TripoSR отдаёт меш в каноническом Z-up пространстве; сервис поворачивает его в Y-up (three.js), опускает основание на `y=0` и масштабирует так, чтобы высота стала равна указанной пользователем.
- Переменные окружения: `TRIPOSR_MODEL`, `MC_RESOLUTION`, `PORT` (по умолчанию 8788), `RECON_MAX_JOBS`.

## Дизайн и тема

Интерфейс построен по принципу **Glassmorphism**: панели — полупрозрачное «стекло» с `backdrop-filter: blur() saturate()`, тонкой светлой обводкой и мягкой тенью; за ними на фоне «плавают» размытые цветовые пятна (mint и cherry), придавая слоям глубину. 3D-вьюпорт рендерится в прозрачный canvas и тоже выглядит стеклянным. Если браузер не поддерживает `backdrop-filter`, есть запасной вариант со сплошным фоном панелей.

Вся тема задаётся **CSS-переменными** в `src/index.css`: переменные проекта + переопределения Bootstrap 5.3 (`--bs-primary`, `--bs-body-bg`, `--bs-border-color` и т.д.), поэтому сменить палитру или сделать светлую тему можно одним блоком переопределений.

| Переменная | Значение | Назначение |
|---|---|---|
| `--cherry` | `#FB7185` | акцент «опасного» (удаление, кнопки danger) |
| `--mint` | `#10B981` | основной акцент (primary, выделение) |
| `--mint-rgb` | `16, 185, 129` | акцент в `rgba()` (свечения, фокусы) |
| `--ink` | `#111827` | почти-чёрный текст (для светлой темы) |
| `--paper` | `#F9FAFB` | светлый фон (для светлой темы) |
| `--night` | `#120E14` | тёмный фон приложения |
| `--night-soft` | `#1E1820` | тёмный фон панелей |
| `--line` | `#E5E7EB` | линии/бордеры (для светлой темы) |
| `--white` | `#FFFFFF` | белый |

Цвета 2D-плана (сетка, стены, проёмы, мебель) подобраны под тёмную тему: сетка — полупрозрачная белая, стены — светлые, выделение — mint, дверь — cherry, окно — teal.

## Координатная модель

Все данные хранятся **в метрах**: `Wall = { a: {x,y}, b: {x,y} }`, где 2D-`y` в 3D становится `z`. Проёмы — `Opening = { id, wallId, kind: 'door'|'window', t, width, height, sill }`, привязаны к стене параметром `t ∈ [0,1]`. Мебель — `PlacedItem = { uid, item, pos:[x,z], rotY }`. Габариты `item.size = [Ш, В, Г]` — модели масштабируются под объявленный размер, поэтому планировка остаётся точной независимо от «родного» масштаба GLB. Коллизии считаются по верхней проекции предметов (SAT для повёрнутых прямоугольников), плоские предметы (`В < 0.1`, ковры) исключены.

## Известные ограничения прототипа

- Автосохранение в localStorage ограничено ~5 МБ — очень тяжёлые фото подложки могут не поместиться (blob-части моделей и подложек лежат в IndexedDB, который объёмнее).
- API-сервер не контейнеризован: dev-режим запускается через `node` (см. «Быстрый старт»).
- Сервис реконструкции TripoSR работает на CPU (без GPU): генерация одной модели занимает ~0.5–5 минут.
